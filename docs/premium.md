# Premium и защита от взлома

Решения от 2026-09-24:
- Бесплатно работает только учёт режимов на главном экране. Любые правки и добавления, выгрузка и перенос данных — **Premium**.
- Защита от взлома — **уровни 1, 2 и 3** (ниже). Сервер для уровня 3 — [docs/server/license-server.md](server/license-server.md).

## Что входит в Premium

| Функция | Где | Premium |
|---|---|---|
| Переключение режимов, автоматическая запись журнала | Главная | нет |
| Выбор страны в начале и конце смены | Главная, экран 10 | нет |
| Таймеры, детали лимитов, предупреждения и уведомления | Главная, экраны 6, 8, 9 | нет |
| Просмотр журнала и всей истории | Журнал | нет |
| «+ Смена» — добавить смену | Журнал, экраны 11–12 | да |
| Изменить смену: время, режимы, страны | Журнал, экран 11 | да |
| Удалить смену | Журнал, экран 11 | да |
| «Добавить вручную» недельный отдых | Недельный отдых, экран 9 | да |
| Корректировка суточного вождения | Главная, экран 7 | да |
| Изменить начало смены | Рабочий день, экран 6 | да |
| Выгрузка отчёта PDF/CSV | Экспорт, экран 16 | да |
| Перенос данных на другое устройство | Ещё → «Перенос на другой телефон» | да |

Когда подписка закончилась, сделанные правки остаются и журнал по-прежнему можно смотреть. Закрываются правки, выгрузка и перенос.

Экраны, которые нужно поправить: 15-Paywall — список функций (правка журнала, выгрузка PDF/CSV, перенос на другое устройство). Экран переноса — шторка «Перенос на другой телефон» в «Ещё» (Фаза 4), замок — в Фазе 5.

### Перенос данных

Решение от 2026-09-29 (владелец): перенос — файлом, без сервера, сделан в Фазе 4 (`app/lib/data/backup/journal_backup.dart`, `app/lib/features/more/transfer_sheet.dart`).

1. Старый телефон: «Ещё» → «Перенос на другой телефон» → «Сохранить журнал в файл». Файл `tachogo-journal-<дата>.json` — записи режимов, смены со странами и заметками, смены итогами, считывания карты, настройки расчёта и уведомлений — уходит в системное «Поделиться»: себе в мессенджер, на почту, в облако.
2. Новый телефон: тот же экран → «Загрузить журнал из файла». Приложение проверяет файл (формат, версия, поля), показывает, за какие дни в нём журнал, и после подтверждения заменяет журнал одной транзакцией. Язык, тема, согласие на аналитику и автоопределение нового телефона не меняются.

Файл не шифруется: это журнал самого водителя, как и CSV-выгрузка, и отправляет его водитель сам.

Что теряет защита. Раньше перенос шёл через сервер лицензий: без действующего токена сервер не принял бы данные, и это была единственная Premium-функция, которую не открыть патчем приложения. Файл можно загрузить и в пропатченное приложение. Владелец решил, что журнал при смене телефона важнее: он нужен водителям уже в бете и без сервера. Правки и выгрузка на новом телефоне по-прежнему требуют подписки. Если перенос файлом начнут использовать для обхода подписки — вернуться к варианту через сервер: старый телефон шифрует журнал (AES-256-GCM, случайный ключ) и загружает на сервер с токеном, новый получает `transferId` и ключ по QR-коду (TRF-01…03, LIC-08, `docs/server/license-server.md`).

Premium (Фаза 5): замок на экране и вторая проверка `EntitlementService` в `JournalBackup`. Что закрывать — сохранение файла, загрузку или оба — открытый вопрос 15 PRD: выгрузка своих данных — ещё и право водителя по GDPR.

## Уровень 1 — покупки через RevenueCat

- Продукты: подписка €5/мес и €30/год, один entitlement `premium`.
- Чеки проверяет сервер RevenueCat у Google и Apple, приложение чеки само не проверяет.
- Включить проверку подписи ответов (Trusted Entitlements). Если `verification` у entitlement равен `failed` — Premium нет. Точный режим и API сверить с актуальной версией `purchases_flutter` при реализации.
- Отмены и возвраты RevenueCat снимает сам. Приложение подписано на обновления `CustomerInfo` и после изменения сразу запрашивает новый токен (уровень 3).
- В приложении только публичные SDK-ключи. Секретный ключ RevenueCat — только на сервере лицензий.
- Логи RevenueCat в release-сборке выключены.

## Уровень 2 — сборка и код

Сборка:
- `flutter build appbundle --release --obfuscate --split-debug-info=<папка символов> --dart-define-from-file=config/prod.json`, для iOS (после релиза, вместе с iOS-версией) — те же флаги в `flutter build ipa`.
- Папка символов не в git. Храним её для каждой версии (без неё не расшифровать краши) и загружаем в crash reporting.
- R8 для Android-части: в release включён по умолчанию, не отключать.

Код:
- Нет флага `isPremium` ни в настройках, ни в БД. В веб-прототипе он есть — это только для демо.
- `EntitlementService` — единственный источник статуса Premium.
- Проверка в двух местах: в UI (замок и paywall) и в слое, который выполняет Premium-операцию (запись ручной правки, выгрузка, перенос). Патч одной кнопки функцию не открывает. Слой уже есть (Фаза 2): ручные правки — `JournalEditRepository`, выгрузка — `ReportExporter`; до Фазы 5 они открыты.
- Автоматическая запись при переключении режима идёт отдельным путём, не через слой ручных правок, чтобы проверка подписки её никогда не задела.
- `tacho_engine` ничего не знает о подписке.

## Уровень 3 — токен доступа от своего сервера

Premium = действующий токен, подписанный сервером лицензий. Статус из RevenueCat нужен только для покупки и как сигнал обновить токен. Сервер выдаёт токен, только если:
- приложение настоящее: Play Integrity на Android (сборка из Google Play, не пересобрана); App Attest на iOS — вместе с iOS-версией после релиза;
- в RevenueCat активен entitlement `premium`.

Что делает приложение:
- При первом запуске создаёт `installId` (UUID v4) и хранит его в защищённом хранилище (`flutter_secure_storage`).
- Запрашивает токен: при запуске, если токена нет или ему больше суток; после покупки, восстановления или изменения `CustomerInfo`. Без сети — работает на текущем токене до его срока (по умолчанию 7 дней).
- Android — Play Integrity, стандартный запрос, через свой platform channel (Kotlin). iOS — App Attest (после релиза): ключ создаётся один раз, первый запрос с attestation, дальше assertion, platform channel на Swift.
- Проверяет токен: подпись Ed25519 по `kid` из списка публичных ключей, `iss`, `ins == installId`, `exp` в будущем, `ent` содержит `premium`. Токен хранится в защищённом хранилище.
- Защита от перевода часов: хранит максимальное увиденное время. Если текущее время меньше него больше чем на 10 минут — Premium выключается до получения нового токена.
- Если сервер недоступен сразу после покупки — показывает «Покупка прошла, активируем Premium» и повторяет запрос. Временный Premium по одному статусу RevenueCat не выдаём: иначе правка кэша на телефоне с root снова открывает функции.

Протокол, переменные и настройка сервера — [docs/server/license-server.md](server/license-server.md).

Настройки приложения (`config/dev.json`, `config/prod.json`, через `--dart-define-from-file`, секретов в них нет):

| Ключ | Что это |
|---|---|
| `LICENSE_API_URL` | Адрес сервера лицензий |
| `LICENSE_PUBLIC_KEYS` | Публичные ключи Ed25519: `k1:<base64>`, через запятую — для смены ключа |
| `REVENUECAT_ANDROID_KEY` | Публичный SDK-ключ RevenueCat для Google Play (`goog_…`) |
| `REVENUECAT_IOS_KEY` | Публичный SDK-ключ RevenueCat для App Store (`appl_…`). После релиза, вместе с iOS-версией |
| `PLAY_CLOUD_PROJECT_NUMBER` | Номер проекта Google Cloud, привязанного к Play Integrity |

## Что закрыто и что нет

| Атака | Уровни 1–3 |
|---|---|
| Поддельная покупка (Lucky Patcher и подобные) | закрыта |
| Подмена ответов сервера через прокси | закрыта |
| Premium после возврата денег | закрыта, с задержкой до срока токена (7 дней) |
| Правка кэша или БД на телефоне с root | закрыта: токен без приватного ключа не подделать |
| Одна подписка на нескольких телефонах | ограничена: восстановление переносит покупку на новое устройство |
| Перенос данных в мод-версии | закрыта: сервер не примет данные без токена |
| Мод-APK с вырезанными проверками — правка журнала и выгрузка | **не закрыта** |

Правка журнала и выгрузка работают без сети, поэтому мод, из кода которого вырезаны проверки, открывает их без токена. Уровень 3 заставляет найти и вырезать больше проверок в обфусцированном коде, но не исключает этого. Полностью закрыть функцию можно, только перенеся её на сервер (уровень 5).

Сервер видит отказы проверки подлинности — по ним видно, есть ли в обороте мод-версии.

## Отложено

- Уровень 4: защита во время работы (RASP, например freeRASP) — только мягкие реакции, без блокировок.
- Уровень 5: платные функции на сервере (синхронизация, резервные копии, ссылка на отчёт, кабинет автопарка).
