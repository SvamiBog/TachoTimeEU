# tacho_engine

Регуляторный движок TachoGo — чистый Dart без зависимостей от Flutter и UI.
Считает остатки по лимитам Регламента (ЕС) 561/2006 и ЕСТР.

Правила: [`docs/domain/eu-561-rules.md`](../../docs/domain/eu-561-rules.md).

```bash
dart test
```

## Инварианты
- Никаких импортов `package:flutter/*` и платформенных плагинов — проверяется в CI.
- Всё время внутри движка — UTC. Локальное время движок не принимает (`ArgumentError`), часовой пояс нужен только для отображения.
- Все функции чистые: на вход журнал и момент `now`, на выход — новый результат. Таймер «тикает», когда приложение пересчитывает с новым `now`.
- Движок ничего не знает о подписке (`docs/premium.md`).
- Каждое правило покрыто тестами на кейсах из регламента.

## Что внутри

| Файл | Что делает |
|---|---|
| `activity_period.dart` | Запись журнала: режим, начало, конец (null — идёт), отметки «паром», «конец дня» и «недельный» |
| `timeline.dart` | Шкала: сортировка, обрезка наложений, склейка соседних записей одного режима, периоды отдыха через паром (ст. 9, регулярный недельный — при рейсе от 8 ч) |
| `shifts.dart` | Смены между суточными отдыхами, перерыв по ст. 7, статус суточного и недельного отдыха, окно 24/30 ч |
| `compliance.dart` | `calculateCompliance` — состояние водителя, таймеры по всем лимитам, предупреждения и нарушения |
| `journal.dart` | Журнал по неделям с подсветкой смен |
| `journal_edits.dart` | Переключение режима и правки задним числом |
| `shift_edits.dart` | Правки смен из журнала: «живая» смена по записям, пересечения и проверка ручных смен, вырезка отдыха, удаление смены |
| `auto_switch.dart` | Автоопределение вождения по скорости GPS: детектор движения и правила переключения (`docs/background.md`) |
| `manual_shift.dart` | Смена, внесённая итогами (до установки приложения) |
| `infringement.dart` | Виды предупреждений и нарушений со статьёй регламента |
| `scope.dart` | `vanRules` — действуют ли правила в рейсе фургона 2,5–3,5 т: с 01.07.2026, международная перевозка и каботаж, исключения ст. 3(h) и 3(ha). Лимиты у фургона те же, что у грузовика и автобуса |
| `forecast.dart` | Прогноз уведомлений: когда появятся предупреждения и нарушения и когда отдых будет набран, если режим не изменится (`forecastAlerts`) |

## Модель состояний

Состояние водителя — это журнал записей, а не отдельная переменная: текущий режим — открытая запись, всё остальное выводится расчётом.

- Переключение (`changeMode`) закрывает открытую запись и открывает новую. Разрешены переходы между любыми режимами, как на тахографе. Повторное нажатие на активный режим ничего не меняет — иначе перерыв дробился бы на части.
- «Завершить день» (`endDay`) — отдых с отметкой `dayEnd`: смена считается завершённой сразу, а не через 9 ч.
- Недельный отдых, объявленный водителем (`endDay(weekly: true)`, `declareRest`, `declareWeeklyRest`), — отметка `weeklyRest`: пока отдых идёт, он недельный и короче 24 ч; прерванный раньше — по длительности.
- «Завершить день» с вождением за день (`endDayWithDriving`) — водитель вводит итог вождения: совпал с записями — они остаются, иначе смена становится ручной с этим итогом (`ManualShift`), а отдых после неё остаётся записью с отметкой `dayEnd`.
- «Паром / поезд» (`setFerry`) — отметка `ferry` у текущей записи; новые записи её наследуют, пока водитель не выключит режим. На пароме автоопределение не переключает режим по движению.
- `ComplianceSnapshot.status` — состояние для главного экрана:

| Статус | Когда |
|---|---|
| `notStarted` | Смены нет и водитель не на суточном отдыхе |
| `driving`, `otherWork`, `availability` | Идёт смена, текущий режим |
| `onBreak` | Отдых внутри смены: меньше 9 ч и не «конец дня» |
| `dailyRest` | Отдых ≥ 9 ч или «конец дня» |
| `weeklyRest` | Отдых ≥ 24 ч |
| `unknown` | Смена идёт, но журнал обрывается разрывом (разрыв — не отдых) |

Отдых становится суточным сам, без действий водителя: открытый отдых через 9 ч завершает смену.

## Таймеры

`calculateCompliance` возвращает значения и остатки по каждому лимиту:

| Лимит | Статья | Поля `ComplianceSnapshot` |
|---|---|---|
| Непрерывное вождение 4:30, перерыв 45 (15 + 30) | 7 | `continuousDriving`, `drivingUntilBreak`, `breakRequired`, `currentBreak` |
| Суточное вождение 9 ч / 10 ч дважды в неделю | 6(1) | `dailyDriving`, `dailyDrivingLimit`, `dailyDrivingRemaining`, `extensionsLeft` |
| Недельное вождение 56 ч | 6(2) | `weeklyDriving`, `weeklyDrivingRemaining` |
| Две недели 90 ч | 6(3) | `fortnightDriving`, `fortnightDrivingRemaining`, `fortnightLimiting` |
| Рабочий день 13 / 15 ч (экипаж 19 / 21 ч) | 8(2), 8(5) | `shiftDuration`, `shiftLimit`, `shiftRemaining`, `dailyRestDeadline` |
| Суточный отдых 11 / 9 ч, не больше трёх сокращённых | 8(2), 8(4) | `offDutyRest`, `dailyRestRemaining`, `reducedRestsLeft` |
| Недельный отдых 45 / 24 ч + компенсация | 8(6) | `weeklyRestRemaining`, `lastWeeklyRest`, `reducedWeeklyRestAvailable`, `compensation` |
| 144 ч между недельными отдыхами | 8(6) | `workWeekDuration`, `weeklyRestDeadline`, `workWeekRemaining` |
| Считывание карты раз в 28 дней | 581/2010 | `cardDaysLeft` |

Предупреждения и нарушения — `infringements`, вид задаёт `InfringementType` (важность, категория, статья), параметры — `time`, `limit`, `requiredBreak`, `count`, `days`.

`forecastAlerts` — моменты для уведомлений: для каждого вида предупреждения или нарушения и для «отдых набран» (`RestMilestone`: перерыв, суточный 11 ч, недельный 45 ч) — первый момент после `now`, когда он появится в снимке, если журнал не изменится. Правила не повторяются: прогноз пересчитывает `calculateCompliance` в контрольных точках (порог минус предупреждение, лимит, лимит + 1 мин, граница недели, 144 ч, компенсация, карта) и уточняет момент до минуты. Что уже есть на момент `now`, в прогноз не входит — водитель это видит на экране. `alertKinds` — какие виды есть в снимке: уведомление о виде, которого уже нет, устарело. Как движок толкует спорные места регламента (экипаж, компенсация, отдых после 144 ч, паром) — [`docs/domain/eu-561-rules.md`](../../docs/domain/eu-561-rules.md).

## Тесты

Перенесены из веб-прототипа (`src/domain/tests`) и служат спецификацией: по файлу на статью, шкала, edge-cases, правки журнала. `properties_test.dart` сравнивает движок с поминутной эталонной моделью на 400 случайных журналах.

`real_data_test.dart` (ENG-20) сверяет нарушения движка за весь журнал с отчётом программы анализа тахографа на обезличенных журналах с настоящих карт — `test/fixtures/real/`, как добавить журнал — README там же.

## Инструменты для данных беты

`tool/` — не часть движка и приложения (импорт `.DDD` в приложение — открытый вопрос 10 PRD), чистый Dart, как и движок:

```bash
dart run tool/ddd.dart summary card.ddd            # сутки, особые условия, нарушения по движку
dart run tool/ddd.dart fixture card.ddd --name driver-a-2026-09 --from 2026-09-01 --to 2026-09-29
dart run tool/ddd.dart compare card.ddd tachogo.csv   # DEV-03: журнал приложения против карты
```

- `src/ddd.dart` — выгрузка карты водителя по Регламенту 2016/799, прил. 1C: только журнал режимов и особые условия (OUT, паром), без имени и номера карты. Проверено на файлах, собранных по спецификации (`test/tool/ddd_test.dart`); первый настоящий файл сверить со сводкой программы анализа по суткам.
- `src/violations.dart` — нарушения за журнал: снимки `calculateCompliance` в конце каждой записи по журналу, каким он был в тот момент.
- `src/fixture.dart` — формат фикстуры ENG-20; `src/compare.dart` — поминутная сверка CSV экспорта приложения с картой, критерий DEV-03 — расхождение не больше минуты.
