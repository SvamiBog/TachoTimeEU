# tacho_engine

Регуляторный движок TachoGo — чистый Dart без зависимостей от Flutter и UI.
Считает остатки по лимитам Регламента (ЕС) 561/2006 и ЕСТР.

Правила: [`docs/domain/eu-561-rules.md`](../../docs/domain/eu-561-rules.md).

```bash
dart test
```

## Инварианты
- Никаких импортов `package:flutter/*` и платформенных плагинов — проверяется в CI.
- Всё время внутри движка — UTC. Локальное время движок не принимает (`ArgumentError`), часовой пояс нужен только для отображения.
- Все функции чистые: на вход журнал и момент `now`, на выход — новый результат. Таймер «тикает», когда приложение пересчитывает с новым `now`.
- Движок ничего не знает о подписке (`docs/premium.md`).
- Каждое правило покрыто тестами на кейсах из регламента.

## Что внутри

| Файл | Что делает |
|---|---|
| `activity_period.dart` | Запись журнала: режим, начало, конец (null — идёт), отметки «паром» и «конец дня» |
| `timeline.dart` | Шкала: сортировка, обрезка наложений, склейка соседних записей одного режима, периоды отдыха через паром (ст. 9) |
| `shifts.dart` | Смены между суточными отдыхами, перерыв по ст. 7, статус суточного и недельного отдыха, окно 24/30 ч |
| `compliance.dart` | `calculateCompliance` — состояние водителя, таймеры по всем лимитам, предупреждения и нарушения |
| `journal.dart` | Журнал по неделям с подсветкой смен |
| `journal_edits.dart` | Переключение режима и правки задним числом |
| `auto_switch.dart` | Автоопределение вождения по скорости GPS: детектор движения и правила переключения (`docs/background.md`) |
| `manual_shift.dart` | Смена, внесённая итогами (до установки приложения) |
| `infringement.dart` | Виды предупреждений и нарушений со статьёй регламента |

## Модель состояний

Состояние водителя — это журнал записей, а не отдельная переменная: текущий режим — открытая запись, всё остальное выводится расчётом.

- Переключение (`changeMode`) закрывает открытую запись и открывает новую. Разрешены переходы между любыми режимами, как на тахографе. Повторное нажатие на активный режим ничего не меняет — иначе перерыв дробился бы на части.
- «Завершить день» (`endDay`) — отдых с отметкой `dayEnd`: смена считается завершённой сразу, а не через 9 ч.
- `ComplianceSnapshot.status` — состояние для главного экрана:

| Статус | Когда |
|---|---|
| `notStarted` | Смены нет и водитель не на суточном отдыхе |
| `driving`, `otherWork`, `availability` | Идёт смена, текущий режим |
| `onBreak` | Отдых внутри смены: меньше 9 ч и не «конец дня» |
| `dailyRest` | Отдых ≥ 9 ч или «конец дня» |
| `weeklyRest` | Отдых ≥ 24 ч |
| `unknown` | Смена идёт, но журнал обрывается разрывом (разрыв — не отдых) |

Отдых становится суточным сам, без действий водителя: открытый отдых через 9 ч завершает смену.

## Таймеры

`calculateCompliance` возвращает значения и остатки по каждому лимиту:

| Лимит | Статья | Поля `ComplianceSnapshot` |
|---|---|---|
| Непрерывное вождение 4:30, перерыв 45 (15 + 30) | 7 | `continuousDriving`, `drivingUntilBreak`, `breakRequired`, `currentBreak` |
| Суточное вождение 9 ч / 10 ч дважды в неделю | 6(1) | `dailyDriving`, `dailyDrivingLimit`, `dailyDrivingRemaining`, `extensionsLeft` |
| Недельное вождение 56 ч | 6(2) | `weeklyDriving`, `weeklyDrivingRemaining` |
| Две недели 90 ч | 6(3) | `fortnightDriving`, `fortnightDrivingRemaining`, `fortnightLimiting` |
| Рабочий день 13 / 15 ч (экипаж 21 ч) | 8(2) | `shiftDuration`, `shiftLimit`, `shiftRemaining`, `dailyRestDeadline` |
| Суточный отдых 11 / 9 ч, не больше трёх сокращённых | 8(2), 8(4) | `offDutyRest`, `dailyRestRemaining`, `reducedRestsLeft` |
| Недельный отдых 45 / 24 ч + компенсация | 8(6) | `weeklyRestRemaining`, `lastWeeklyRest`, `reducedWeeklyRestAvailable`, `compensation` |
| 144 ч между недельными отдыхами | 8(6) | `workWeekDuration`, `weeklyRestDeadline`, `workWeekRemaining` |
| Считывание карты раз в 28 дней | 581/2010 | `cardDaysLeft` |

Предупреждения и нарушения — `infringements`, вид задаёт `InfringementType` (важность, категория, статья), параметры — `time`, `limit`, `requiredBreak`, `count`, `days`.

## Тесты

Перенесены из веб-прототипа (`src/domain/tests`) и служат спецификацией: по файлу на статью, шкала, edge-cases, правки журнала. `properties_test.dart` сравнивает движок с поминутной эталонной моделью на 400 случайных журналах.
